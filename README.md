# 쿨시티 그리드 (CoolCity Grid)

**2026년 지능형 과학실 ON 연계 공동탐구 전국대회 · 주제6 열섬현상(자유)**
_"열섬현상 저감을 위해 AI를 활용하여 도심을 설계해 보자"_

도시를 격자에 직접 칠하면 지표 재질별 열수지를 확산 모델로 계산해 온도 지도를 그립니다.
그 위에서 AI(담금질 기법)가 두 가지 질문에 답합니다 — **같은 녹지로 어디에 심어야 가장
시원한가**, 그리고 **정해진 예산으로 어떤 대책을 어디에 써야 하는가**. 여기에 변인을 하나씩
바꿔가며 반복 측정하는 **탐구 실험실**, 실측값으로 계수를 맞추고 **홀드아웃으로 검증**하는
보정 기능, 결과를 그대로 뽑아주는 **PDF 보고서 생성기**가 붙어 있습니다.

## 실행 방법

`coolcity-grid.html` **파일 하나**를 브라우저로 열면 끝입니다. 설치도, 서버도, 인터넷 연결도
필요 없습니다(웹폰트만 온라인일 때 적용되고, 오프라인이면 시스템 글꼴로 대체됩니다).

```bash
start coolcity-grid.html
```

외부 라이브러리를 CDN에서 받아오지 않습니다. PDF 생성에 쓰는 jsPDF 2.5.1(MIT)은 파일 안에
직접 넣어두었습니다.

## 무엇을 할 수 있나

| 기능 | 설명 |
| --- | --- |
| 도시 설계 캔버스 | 18×18 격자를 8가지 재질(건물·도로·공원·물·빈터·**쿨루프**·**차열포장**·**가로수길**)로 칠합니다. 되돌리기/다시 실행과 키보드 전용 조작을 지원합니다. |
| 실시간 열 지도 | 재질별 열원값을 격자 확산으로 계산해 칸마다 예상 기온을 색으로 표시합니다. 시간대·바람·기준기온을 바꾸면 즉시 반영됩니다. |
| AI 배치 최적화 | 녹지 **칸 수는 그대로 두고 위치만** 바꿔 거주역 평균기온을 낮추는 배치를 담금질 기법으로 탐색합니다. |
| AI 종합 설계 | 정해진 **예산** 안에서 **어떤 대책을 어디에** 쓸지 AI가 함께 정합니다. 칸당 비용이 다르므로(지붕 도색 1점, 건물 철거 후 공원 8점) 예산이 적으면 값싼 표면 대책에, 예산이 커지면 녹지 조성에 몰립니다. 예산을 바꿔가며 돌리면 **예산-저감량 곡선**이 나옵니다. |
| 재현성 | 무작위 배치와 AI 탐색이 모두 하나의 **시드**에서 나옵니다. 같은 시드 + 같은 도시 = 같은 결과이므로, 보고서에 적은 수치를 나중에 그대로 재현할 수 있습니다. 사용한 시드는 결과·CSV·PDF에 함께 기록됩니다. |
| 탐구 실험실 | 변인 하나만 바꿔가며 반복 측정합니다 — ① 녹지 비율 ② 시간대 ③ 바람 세기 ④ 녹지 배치 형태 ⑤ 저감 대책별 효과 ⑥ 예산 → 저감량. 그래프·표·CSV·해석 문장을 자동으로 만듭니다. |
| 통계 | 오차막대와 표의 ±95%CI는 **평균의 95% 신뢰구간**(표준편차가 아니라 표준오차 기반, 작은 n에 맞춰 t분포 사용)입니다. 두 조건의 구간이 겹치는지로 "이 차이가 배치 운으로 설명되는지"를 결론 문장이 직접 말해 줍니다. CSV에는 표준편차·표준오차·신뢰구간이 모두 들어갑니다. |
| 배치도 이미지 불러오기 | 지도 캡처와 위성·항공 사진을 **자동으로 구분**해 각각 다른 규칙으로 분류합니다(지도에서는 도로가 가장 밝고, 항공사진에서는 가장 어둡습니다). 임계값은 이미지 자체의 밝기 분포에서 뽑아 어둡거나 밝게 찍힌 캡처에도 대응하고, 판단이 애매한 칸은 깜빡여 표시합니다. |
| 실측 보정 | 현장에서 잰 재질별 평균 온도로 열원 계수를 맞추고 MAE·RMSE·R²를 냅니다. **보정에 쓰지 않은 빈터**로 홀드아웃 검증까지 합니다. |
| 설계안 A/B/C | 팀이 만든 설계안을 슬롯에 저장해 같은 조건으로 다시 계산해 비교합니다. |
| 3D 조감도 | 시간대에 따라 하늘·그림자·창문 불빛이 바뀌는 아이소메트릭 도시 뷰(캔버스 2D로 직접 그림). |
| 결과 내보내기 | 격자 원자료 CSV, 실험 CSV·그래프 PNG, 그리고 표지·요약·조감도·실험별 페이지·종합 결론까지 담은 PDF 보고서. |

## 시뮬레이션 모델

각 칸의 온도는 재질별 열원값에서 출발해 이웃 칸과 열이 섞이는 과정을 10회 반복해 얻습니다
(정상상태에 이미 도달한 횟수입니다). 들어간 가정은 다섯 가지입니다.

1. **시간대** — 태양 복사를 0.25배(야간)~1.2배(오후 1~2시)로 스케일링
2. **바람의 이류** — 바람이 불어오는 쪽 이웃 칸에 가중치를 더 줘 하풍 방향으로 열이 더 퍼짐
3. **열린 경계** — 격자 바깥을 기준기온의 주변 공기로 보고 가장자리 칸이 열을 주고받음
4. **환기 효과** — 바람이 셀수록 지표→공기 열전달이 빨라져 열섬 세기 자체가 최대 35% 감소
5. **저감 대책 재질** — 쿨루프·차열포장은 원래 재질보다 낮은 열원값을 갖는 것으로 모델링
6. **가로수길** — 도로를 그대로 둔 채 수관을 덮은 길(+3.0℃). 땅을 차지하지 않는 것이 공원과
   다르고, 수관이 실제 높이를 가지므로 아래 ⑦의 그늘 계산을 통해 **옆 칸 도로까지 식힙니다**
   (측정: 가로수에서 먼 도로 29.0℃ → 바로 옆 칸 27.2℃)
7. **건물 높이** — 서로 반대 방향인 두 효과. 낮에는 태양 쪽 높은 건물이 그늘을 드리워 일사를 깎고,
   밤에는 같은 높이가 하늘을 가려(SVF↓) 열이 빠져나가지 못하게 가둡니다. 그래서 빽빽한 블록은
   한낮엔 트인 곳보다 시원하고 새벽엔 더 덥습니다

AI 종합 설계가 쓰는 대책별 비용(건물→쿨루프 1점, 도로→가로수길 2점, 빈터→녹지 2점,
도로→차열포장 3점, 도로→녹지 5점, 건물 철거 후 녹지 8점)은 **사업 난이도를 상대 점수로
가정한 값**이며 실제 공사비가 아닙니다. 차도 전면 재포장이 도로변 가로수 식재보다 큰
공사라는 점을 반영했습니다. 칸당 냉각 효과만 보면 녹지가 늘 이기기 때문에, 비용을 매기지 않으면
"전부 녹지"라는 자명한 답만 나옵니다 — 현실에서 쿨루프가 존재하는 이유가 건물을 헐 수
없기 때문이라는 점을 모델에 반영한 것입니다.

### 이 모델이 다루지 못하는 것

정직하게 밝혀 둡니다. PDF 보고서 마지막 페이지에도 같은 내용이 실립니다.

- 열이 이웃으로 퍼지는 거리가 **1~2칸**으로 제한됩니다. 공원 하나가 수백 미터 밖까지 식히는
  실제 냉각 범위는 재현하지 못합니다.
- 건물 높이는 그늘과 하늘시계지수(SVF)로만 들어갑니다. 높이 자체는 칸마다 정해진 가상값이고,
  실제 건물의 층수·향·형태를 반영한 것이 아닙니다.
- 습도·증발산의 시간 변화, 에어컨 실외기 같은 인공 배열, 지형과 해풍은 빠져 있습니다.
- 쿨루프·차열포장 계수는 문헌상 표면온도 저감 폭을 이 모델의 상대 눈금으로 옮긴 **가정치**이며,
  그대로 인용할 수 있는 실측 계수가 아닙니다.
- AI 최적화는 확률적 탐색이라 시드에 따라 다른 답을 냅니다. 같은 시드로는 그대로 재현되지만,
  결론을 낼 때는 시드를 몇 개 바꿔 결과의 폭을 함께 보고하는 편이 정확합니다.

**절대 온도가 아니라 조건 사이의 상대 비교로 읽어 주세요.** 실측 보정과 홀드아웃 검증을 거치면
신뢰 구간을 스스로 확인할 수 있습니다.

## 인용한 통계

도시 프리셋의 녹지율·인구밀도는 KOSIS 국가통계포털 지역지표, 열대야·폭염 일수는 기상청
「2024년 여름철 기후특성」(2024.9.5) 및 부산지방기상청 자료입니다. 건물·도로·물의 비율은
인구밀도를 참고해 이 도구가 추정한 값이며, 화면에도 그렇게 표시됩니다.
